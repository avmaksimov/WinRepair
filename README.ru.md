# WinRepair

**WinRepair** — утилита диагностики и восстановления Windows 7/8/8.1/10/11 и соответствующих выпусков Windows Server с помощью штатных средств DISM и SFC. Она помогает выбрать установочный образ Windows, если обычный источник восстановления не сработал.

**[English documentation](README.md)**

> [!IMPORTANT]
> Запускайте с правами администратора и заранее сохраняйте важные данные. Утилита может менять системные файлы и хранилище компонентов через DISM/SFC, но не изменяет политики WSUS, не очищает кэш обновлений, не удаляет компоненты и не перезагружает Windows автоматически. Восстановление не гарантируется.

## Запуск без CMD-файла

Запустите `WinRepair.ps1` через контекстное меню **«Выполнить с помощью PowerShell»** либо из открытой консоли:

```powershell
& '.\WinRepair.ps1'
```

При недостатке прав скрипт сам запрашивает UAC и запускает новый PowerShell с тем же PS1 (по аналогии с WinRE-Manager). Открытая консоль пользователя остаётся доступной; новое окно после завершения ожидает нажатия клавиши. При запуске с сетевого диска скрипт пытается заменить букву на UNC-путь. У новой учётной записи может не быть доступа к общей папке — тогда запустите локальную копию.

## Требования

- Достаточно одного `WinRepair.ps1`; CMD-файл и другие скрипты для восстановления не требуются.
- `WinRepair.ps1` работает с Windows PowerShell 2.0 и выше (включая штатный PowerShell Windows 7), на 32- и 64-битных системах. Для отдельного **`update.ps1` нужен Windows PowerShell 5.1** и интернет.
- Нужны права администратора. При необходимости WinRepair запросит UAC. Для сетевого диска скрипт пытается преобразовать букву в UNC, поскольку повышенный процесс может не видеть подключённые сетевые диски.
- Windows 8 и Windows Server 2012 и новее поддерживают DISM `/RestoreHealth`. На Windows 7 / Server 2008 R2 доступен SFC; для хранилища компонентов используйте CheckSUR (KB947821).

## Как работает восстановление

PowerShell-журнал сохраняется в `%ProgramData%\WinRepair\Logs`, штатные журналы — `%windir%\Logs\DISM\dism.log` и `%windir%\Logs\CBS\CBS.log`.

На клиентских Windows сначала выполняется `DISM /Online /Cleanup-Image /RestoreHealth` без ISO. При ошибке программа предлагает попробовать WIM/ESD. Для подтверждений используется **английская раскладка `Y/N`**; Enter по умолчанию означает «Да», когда это указано в запросе. На Windows Server ISO предлагается до первой попытки DISM; Enter позволяет продолжить без образа. После DISM запускается `SFC /scannow`, даже если DISM не справился, кроме случая прерывания.

Поиск образов ограничен стандартными расположениями `sources\install.wim`, `sources\install.esd` и файлами с такими же именами в корнях доступных дисков; полного рекурсивного поиска нет. Если образ не найден, смонтируйте ISO и введите латинскую **букву диска** без двоеточия, например `E`, либо полный путь к WIM/ESD. Программа показывает редакции, проверяет метаданные и предлагает индекс. Автоматический выбор допустим только при однозначном совпадении; иначе индекс подтверждается вручную. Показываются версии установленной Windows и выбранного образа, при несовпадении выводится предупреждение.

DISM и SFC запускаются как штатные консольные процессы, сохраняют собственный прогресс и настоящие коды завершения. `/LimitAccess` не используется, чтобы не запрещать резервный источник Windows Update; однако групповые политики, WSUS и сеть могут ограничивать обращение к Microsoft Update. Программа не скачивает ISO, не устанавливает обновления Windows и не меняет политики обновления.

## Что делать при ошибке DISM, включая 0x800F0915

Совпадение редакции Windows и индекса WIM/ESD **не гарантирует наличия всех нужных файлов и версий компонентов**. При управлении обновлениями через WSUS резервный источник Microsoft Update может быть недоступен. Если в CBS.log встречается `0x800F0954`, проверьте настроенный источник восстановления и политику загрузки ремонтных компонентов; утилита эти настройки не изменяет.

1. Изучите `%windir%\Logs\CBS\CBS.log` и `%windir%\Logs\DISM\dism.log`, чтобы определить точный повреждённый или отсутствующий компонент. Для быстрого просмотра:

   ```powershell
   Select-String "$env:windir\Logs\CBS\CBS.log" -Pattern '0x800f0915','CSI Payload Corrupt','CBS_E_','Missing replacement','Failed to resolve' | Select-Object -Last 40
   ```

2. Подберите источник восстановления, соответствующий редакции, языку, архитектуре, семейству сборок и необходимым обновлениям установленной ОС. Если восстановить хранилище по-прежнему не получается, можно рассмотреть восстановительную установку Windows поверх существующей с сохранением приложений и данных (если этот вариант поддерживается).
3. Успешный SFC **не доказывает**, что хранилище компонентов восстановлено. Повторите DISM либо запустите `DISM /Online /Cleanup-Image /ScanHealth` для оценки состояния.

См. документацию Microsoft: [восстановление образа](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/repair-a-windows-image) и [настройка источника](https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/configure-a-windows-repair-source).

## Установка и обновление через GitHub

После публикации репозитория `avmaksimov/WinRepair` в ветке `main` откройте **Windows PowerShell 5.1**, перейдите в нужный каталог установки и скачайте/запустите обновляющий скрипт:

```powershell
Invoke-WebRequest -Uri ('https://raw.githubusercontent.com/avmaksimov/WinRepair/main/update.ps1?cacheBust=' + [guid]::NewGuid().ToString('N')) -Headers @{ 'Cache-Control' = 'no-cache'; 'Pragma' = 'no-cache' } -OutFile '.\update.ps1' -UseBasicParsing
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\update.ps1'
```

`update.ps1` адаптирован из [WinRE-Manager](https://github.com/avmaksimov/WinRE-Manager/blob/main/install.ps1). Папка установки — **текущий рабочий каталог PowerShell**, а не папка, в которой находится сам `update.ps1`. Он скачивает ZIP репозитория через `Invoke-WebRequest`, распаковывает во временном каталоге, пропускает файлы и папки, чьи имена начинаются с точки, сравнивает SHA-256 и показывает для каждого файла `INSTALL`, `REPLACE` или `UNCHANGED`. Перед изменениями задаётся **один вопрос `Y/N`**. Изменённые файлы сначала копируются рядом с целевыми под суффиксом `.new`, затем заменяются через перемещение. Неизменённые и посторонние файлы не трогаются, старые копии и журналы установщика не создаются. Вложенные папки и новые файлы обнаруживаются автоматически.

**Windows 7 с PowerShell 2.0:** используйте ручное скачивание ZIP и запуск `WinRepair.ps1`. Установщик требует PowerShell 5.1. Интернет нужен обновляющему скрипту, а не для штатной работы SFC.

Программа обновления не удаляет старые `CheckWin-smart.cmd`, `CheckWin-smart.ps1` и прежние журналы; ненужные старые файлы можно удалить вручную. В новом комплекте **нет CMD**.

## Ограничения

- Разделённые образы `install.swm` не поддерживаются.
- Выбранный образ может иметь другую сборку или не содержать требуемых актуальных компонентов; совпадение редакции ещё не гарантирует успешный ремонт.
- WinRepair не заменяет автономное восстановление и переустановку ОС при серьёзных повреждениях.
- При Ctrl+C выполняется попытка прервать текущую операцию и весь сценарий; после прерывания проверяйте состояние Windows и журналы.
